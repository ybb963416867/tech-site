# Codex 技能说明

## 派生

**用途**：为当前对话创建一个新的分支工作树，便于并行尝试不同修改方案。

**怎么用**：当你想在不影响当前会话的情况下继续另一个方向时，选择“派生”即可，让 Codex 在新的本地或全新工作树里继续处理。

**什么时候用**：适合做多个实现方案对比、同时处理互不影响的任务，或想保留当前上下文不被打断时使用。

## 状态

**用途**：查看当前对话 ID、上下文使用情况和额度限制。

**怎么用**：直接点“状态”或输入对应命令，Codex 会显示当前会话的运行信息。

**什么时候用**：适合在长对话、重度改代码或担心上下文快满时查看，帮助你判断是否需要压缩上下文或新开会话。

## 目标

**用途**：设置一个让 Codex 持续跟进的长期目标。

**怎么用**：把你的大目标写进去，比如“把这个项目的测试补齐”或“逐步重构登录模块”，之后 Codex 会围绕这个目标持续推进。

**什么时候用**：适合跨多个回合完成的大任务，或者你希望 Codex 保持稳定方向时使用。

## 计划模式

**用途**：先让 Codex 制定计划，再进入具体执行。

**怎么用**：在不急着改文件的情况下，先开启计划模式，让 Codex 先分析任务、拆解步骤、确认方案，然后再开始实施。

**什么时候用**：适合需求复杂、改动范围大、需要先评估风险或拆分任务的时候使用。

## 记忆

**用途**：让 Codex 生成或更新可复用的“记忆”，用于保留偏好、约定或项目习惯。

**怎么用**：当你希望 Codex 记住某些长期偏好时使用，例如代码风格、常用框架、命名习惯等。

**什么时候用**：适合团队协作、固定开发规范、或者你不想每次都重复说明同一类偏好时使用。

## MCP

**用途**：查看 MCP 服务器状态。

**怎么用**：点击“MCP”后，Codex 会展示已连接的 MCP 服务、状态和可用能力。

**什么时候用**：当你的工作流依赖外部工具、文件系统、数据库或其它 MCP 服务器时，先检查这里最合适。

## 个性

**用途**：选择 Codex 的回应风格。

**怎么用**：在“个性”里切换回答语气和表达方式，让 Codex 更偏简洁、详细、正式或更适合你的沟通习惯。

**什么时候用**：适合你希望统一输出风格、或者不同任务需要不同表达密度时使用。

## 代码审查

**用途**：审查未暂存的更改，或者与某个分支进行比较。

**怎么用**：选择“代码审查”后，让 Codex 检查当前修改、指出潜在问题，或者对比分支差异并给出建议。

**什么时候用**：适合在提交前做质量检查、检查逻辑问题、或者准备合并分支时使用。

## 侧边

**用途**：在临时分支中发起侧边对话。

**怎么用**：当你想让 Codex 在一个独立的临时分支里继续讨论或尝试时，可以选择“侧边”。

**什么时候用**：适合探索性问答、临时实验、或者不想污染主工作流时使用。

## 压缩

**用途**：压缩当前对话上下文，减少已使用的上下文占用。

**怎么用**：当对话越来越长、上下文占用接近上限时，使用“压缩”把前面的内容总结保留，释放空间。

**什么时候用**：适合长会话、连续多轮编辑、或模型开始丢失早期细节时使用。

## 反馈

**用途**：发送关于当前聊天或功能的反馈。

**怎么用**：点击“反馈”并描述问题、建议或体验，必要时附带上下文信息。

**什么时候用**：当你遇到 bug、结果不符合预期，或者想给产品建议时使用。

## 宠物

**用途**：唤醒或收起桌面宠物。

**怎么用**：点击“宠物”即可控制桌面宠物的显示状态。

**什么时候用**：主要是界面交互功能，适合想切换视觉元素或减少干扰时使用。

## 快速

**用途**：切换到更快的响应模式，显示为 1.5x speed，并会增加使用量。

**怎么用**：打开“快速”后，Codex 会优先给出更快的响应，适合追求效率的场景。

**什么时候用**：适合赶时间、需要快速试错、或在高频交互中提高效率时使用。

## 推理模式

**用途**：调整模型的推理强度，图片里显示为“中”。

**怎么用**：在“推理模式”里切换不同推理档位，让 Codex 在速度和思考深度之间做权衡。

**什么时候用**：简单任务可用较低推理，复杂重构、调试、方案设计时适合使用更强推理。

## 模型

**用途**：选择当前对话使用的模型，图片里显示为 GPT-5.5。

**怎么用**：点击“模型”后切换可用模型，不同模型在速度、能力和成本上可能不同。

**什么时候用**：当任务类型变化明显时使用，例如日常问答、复杂编程、审查任务可能适合不同模型。

## 使用建议

实际使用时，可以把这些技能理解成三类：会话管理类、工作流控制类、输出风格类。

一般先用“状态”“压缩”“模型”“推理模式”来控制环境，再按任务需要使用“目标”“计划模式”“代码审查”或“派生”。

如果你是在做正式开发，最常组合使用的是“目标 + 计划模式 + 代码审查 + 压缩”。
