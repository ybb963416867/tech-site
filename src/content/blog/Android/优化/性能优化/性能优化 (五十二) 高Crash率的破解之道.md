# 高Crash率的破解之道

## Crash相关指标

- uv、PV crash率

1. UV Crash率 = Crash  UV/DAU
2. uv方便评估用户影响范围，结合PV
3. 注意：沿用同一种衡量方式

- java、Native Crash率

- 启动、重点流程Crash率

1.   影响最严重的Crash
2. 结合客户端容灾

- 增量、存量Crash率

1. 增量Crash值最新版本重点
2. 存量Crash是持续啃的硬骨头
3. 优先解决增量、持续跟进存量

- Crash率评价

1. 务必在千分之二以下
2. Crash率万分位优秀

## Crash关键问题

- 尽可能还原Crash现场

1. 堆栈、设备、OS版本、进程、线程名、Logcat
2. 前后台、使用时长、APP版本、小版本、渠道
3. Cpu架构、内存信息、线程数、资源包信息、行为日志
4. APM后台聚合展示

1. Crash现场信息
2. Crash Top机型、Os版本、分布版本、区域
3. Crash起始版本、上报趋势、是否新增、持续、量级

- 整体架构

1. 采集层：错误堆栈、设备信息、行为日志、其他信息
2. 处理层：数据清洗、数据聚合、纬度分类、趋势对比
3. 展示层：数据还原、纬度信息、起始版本、其他信息
4. 报警层：环比、同比、邮件、IM、电话

- 责任归属

1. 专项小组轮值
2. 自动匹配分配
3. 处理流程全记录

- 单个Crash处理方案

1. 根据堆栈及现场信息找答案
2. 找共性：机型、OS、实验开关、资源包
3. 线下复现、远程调试

## Crash治理方案

- 解决线上常规Crash
- 系统级Crash尝试Hook绕过
- 疑难Crash重点突破、更换方案
